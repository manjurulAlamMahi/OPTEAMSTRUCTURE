Project Assignment & Handling

How a project is assigned, who owns it, how tasks are given and who handles support messages.

  1. PC · Project Coordinator

    Assign to an OM

    Assigns the new project to Operations Manager 1 or Operations Manager 2.

  2. OM · Operations Manager

    Assign to a PM

    Picks one of their 3 Project Managers whose team fits the project's stack.

  3. PM · Project Manager

    Own the project

    From here the PM handles the whole project and picks the developers from their team.

  4. DEV · Developer

    Work on the tasks

    Works only on the tasks the PM gives, on time, and reports back to the PM.

PM · Project Manager

One owner for the whole project

After assignment, everything about the project goes through its PM:

  • Client meetings
  • Client messages & progress updates
  • Assigning developers to the project
  • Giving and tracking daily tasks
  • Deadline checks until delivery
PM → DEV

Tasks are specific and written down

No vague instructions. Every task says which client, what to do and by when.

Example

Today: Client X, have the update for the Payment module ready.

What
What needs to be built or changed
Expected
What the client is looking for
Deadline
When it must be ready

When a client sends a new request, the PM writes it down in this format before giving it to a developer.

OM · Operations Manager

Support messages go through the OM

The PM does not write support messages.

  1. The PM tells the OM the project's story: status, progress, issues.
  2. The OM writes the support message from that.
  3. The OM sends it and keeps the support messages up to date.
  • One project, one PM. Meetings, client messages and updates all go through the assigned PM.
  • Clear tasks only. Developers get specific, written tasks with a deadline, not open-ended requests.
  • Support messages belong to the OM. The PM gives the story, the OM writes and sends.
